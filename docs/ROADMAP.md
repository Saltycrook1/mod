# Roadmap

## Next: validate the tornado alpha

Complete real two-client synchronization, full dedicated-server restart and sustained server/client measurements first. Tune the funnel, warning visibility and HUD against recorded gameplay. Add receiver range/scale labels and evaluate crowded-entity fairness. Establish behavior with doors, slabs and broken shelter walls before broadening shelter claims.

## Then: strengthen survival and operations

Improve forecasts to distinguish frozen fronts in the receiver itself. Add explicit protection inspection/removal and support for established claim APIs. Make protection migration and recovery tools reviewable. Improve storm motion with bounded course changes and variable natural duration, while preserving clear minimum warning time. Add local rain/thunder atmosphere only with accessibility controls and measured render/network costs.

## Later: presentation and compatibility

Create original wind/siren audio and richer cloud/debris rendering with strict budgets. Test common optimization/shader combinations on specified hardware, add repeatable client screenshots and expose local settings through a usable screen. Expand multiplayer soak tests and document tested player/entity limits.

## Further disasters remain deferred

Do not add floods, earthquakes, wildfires or a disaster menu until the tornado milestone clears the release checklist. A future disaster needs distinct simulation, readable warnings, meaningful counterplay, bounded work, persistence and its own validation scenarios. A visual effect or command stub does not count as an implemented disaster.
